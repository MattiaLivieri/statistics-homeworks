Private key → public key on a toy curve

A private scalar k and a public base point G determine the public point Q = kG. Scalar multiplication means repeated point addition, not multiplying the coordinates by k. The toy example below makes every intermediate point visible.

1. Curve, base point and private key

E(F₁₇): y² ≡ x³ + 7 (mod 17) a = 0, b = 7, p = 17; G = (1, 5); k = 6 G is valid: 5² ≡ 8 ≡ 1³ + 7 (mod 17).

The curve is nonsingular because 4a³ + 27b² ≡ 14 ≠ 0 (mod 17). It contains 17 affine points, plus the identity O, the point at infinity. Therefore #E(F₁₇) = 18. The selected point G = (1, 5) has order 9: 9G = O. Its canonical nonzero private scalars are 1 ≤ k ≤ 8. The program also accepts larger values to demonstrate the periodicity (k + 9)G = kG.

2. Point-addition rules

For two finite points P = (x₁, y₁) and R = (x₂, y₂), division means multiplication by a modular inverse in F₁₇. All values below are reduced modulo 17.

If P ≠ R: λ = (y₂ − y₁) · (x₂ − x₁)⁻¹ If P = R: λ = (3x₁² + a) · (2y₁)⁻¹ x₃ = λ² − x₁ − x₂ y₃ = λ(x₁ − x₃) − y₁ P + R = (x₃, y₃)

The exceptional cases are essential: P + O = P; P + (−P) = O, where −P = (x, −y mod 17); and doubling a point with y = 0 gives O. The code checks these cases before attempting an inverse.

For example, doubling G uses 10⁻¹ ≡ 12, so λ ≡ 3 · 12 ≡ 2. Thus x₂G ≡ 2² − 1 − 1 = 2 and y₂G ≡ 2(1 − 2) − 5 ≡ 10: 2G = (2, 10).

4. Statistical exploration

Method. For each valid base, enumerate every canonical scalar k = 1, …, r − 1, where r = ord(G). Exclude O from coordinate and bit statistics rather than assigning it artificial coordinates. Each coordinate is encoded as exactly five bits; the point encoding is x[5] || y[5], most significant bit first. Reference findings. For G = (1, 5), the eight nonzero scalars produce eight different points. The x values {1, 2, 5, 12} occur twice each; the y values {1, 5, 7, 8, 9, 10, 12, 16} occur once each. Thus outputs are uniform over these eight points under a uniform choice of valid scalar, but coordinates are not uniform over F₁₇. There are 26 one bits out of 80 encoded bits, or 32.50%. The top x bit is always zero. A fixed-width binary representation of a small constrained field need not look like independent fair bits.

Correlations. In the reference case, Pearson corr(k, x) = 0 and corr(k, y) ≈ 0.2978. Zero linear correlation does not imply independence: x(kG) = x((r − k)G), and all outputs are deterministically related by Q(k + 1) = Q(k) + G. The x symmetry actually explains the zero correlation over the complete nonzero scalar range.

Avalanche-like experiment. Encode valid scalars using four bits. For every unordered pair of valid scalars differing in exactly one input bit, measure the Hamming distance between their 10-bit point encodings. There are nine such pairs for the reference base; their mean distance is 44 / 9 ≈ 4.889 bits, with minimum 2 and maximum 7. Out-of-range scalars and zero are excluded. This small average is descriptive; it does not establish the strict avalanche criterion, which would concern each input/output bit pair over a suitable large domain.

5. What is meaningful cryptographically?

Scalar multiplication is deterministic and efficient, while recovering a uniformly chosen large scalar from its public point is the elliptic-curve discrete logarithm problem (ECDLP). The toy group is too small to make inversion difficult: the answer can be found by testing at most eight canonical scalars. Even the order-18 base is unsuitable for real cryptography because its order is tiny and composite.

On a large prime-order subgroup, nonzero canonical scalars map bijectively to non-identity points. There are no scalar-to-point collisions within that domain, although x coordinates repeat for opposite points. A cryptographic hash instead maps arbitrary-length messages into a fixed-size digest and necessarily has collisions. Preimage resistance, second-preimage resistance, collision resistance and good diffusion are hash-function goals. Point multiplication has exploitable public algebraic structure by design, enabling signatures and other public-key protocols. Uniform sampling of private scalars and hardness of ECDLP matter more than whether a particular point encoding passes a hash-style bit test.

Ethereum uses the same equation shape, but secp256k1 has p = 2²⁵⁶ − 2³² − 977 and a base point of large prime order n, with cofactor 1. Its canonical keys satisfy 1 ≤ k < n. Generic classical ECDLP attacks take on the order of √n ≈ 2¹²⁸ group operations. This comparison explains why the toy arithmetic is educational rather than secure. [1]

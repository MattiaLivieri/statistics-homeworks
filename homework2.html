1. Elliptic-curve encryption and decryption

The previous homework introduced scalar multiplication, Q = dG. Its small-field example used modulus 17. This homework uses the actual secp256k1 curve and standard generator G, but deliberately limits the recipient's private key to 1 ≤ d ≤ 4095. This restriction makes the required attack practical.

y² = x³ + 7 (mod p), with p = 2²⁵⁶ − 2³² − 977 Private key: d ∈ {1,…,4095} Public key: Q = dG

Scalar multiplication alone does not encrypt a message. The toy encryption scheme uses an ephemeral ECDH shared point to derive an AES key:

  1. Key generation: the recipient chooses private d and publishes Q = dG. The example uses d = 1337.
  2. Encryption: the sender chooses a fresh random scalar r in the full range 1,…,n−1, where n is the generator's order, and computes R = rG and S = rQ. HKDF-SHA256 derives a 256-bit key K from S. AES-256-GCM encrypts the UTF-8 message with K and a fresh 96-bit IV.
  3. Transmission: send R, the public salt and IV, and the ciphertext with its authentication tag. Q is public. The private values d, r, S and K are not transmitted.
  4. Decryption: the recipient computes S′ = dR, derives the same K, verifies the tag and decrypts the ciphertext.
S′ = dR = d(rG) = r(dG) = rQ = S

Q allows encryption without revealing d; d enables decryption. The temporary r creates the sender's contribution to the shared secret. In the code, HKDF uses the compressed shared point, a 16-byte salt and public context; AES-GCM also authenticates that context. This is an educational ECC hybrid, with an intentionally weak recipient key range.

2. Caesar cipher and comparison

Represent A–Z as 0–25. For secret shift k, encrypt with c = (m + k) mod 26 and decrypt with m = (c − k) mod 26. The program handles upper- and lowercase ASCII letters and preserves case, spaces, punctuation, digits and other characters. Both directions use the same secret key.

Both schemes transform plaintext into ciphertext and use a key to recover the original message. Their key relationships and statistical behavior differ:

PropertyCaesar cipherECC toy hybrid

A Caesar shift preserves letter-frequency entropy because it only renames the alphabet. It does not flatten the distribution. ECC ciphertext should not be analyzed as English letters: its bytes are displayed here in hexadecimal, whose symbols are merely an encoding.

3. Statistical cryptanalysis of Caesar

The known language is English. The training corpus is Jane Austen's Pride and Prejudice (541,355 ASCII letters). Count each letter and estimate its probability pᵢ. A small smoothing value of 0.1 keeps expected frequencies positive.

pᵢ = (training countᵢ + 0.1) / (training letters + 26 × 0.1) χ²(k) = Σᵢ (observedᵢ(k) − Lpᵢ)² / (Lpᵢ)

For each of the 26 candidate shifts, compute the decrypted letter counts, where L is the ciphertext's number of ASCII letters. Return the shift with the smallest χ² score. Ties use the smaller shift. This ranks candidates by their agreement with English frequencies; the score is not proof that a candidate is correct.

Effectiveness: recovery succeeds in 47.02% of the five-letter trials, 74.90% at ten letters and 93.37% at twenty letters. It reaches 100% at 100 letters in this test set. Longer representative samples generally estimate English frequencies more accurately.


Limitations: short messages, names, abbreviations, unusual vocabulary or a different language can favor an incorrect shift. The method ignores letter order. These rates apply to the tested books and windows; overlapping samples and one test book do not establish a guarantee for all English text.






4. Recovering the restricted ECC private key


The attacker knows the public key Q, generator G and the restriction 1 ≤ d ≤ 4095. Generate successive multiples of G and stop when one equals Q:


A ← point at infinity
for j = 1,…,4095:
    A ← A + G
    if A = Q:
        recovered private key ← j
        S ← jR
        derive K and decrypt the ciphertext


The search takes at most 4095 point additions and comparisons. It uses only Q and the bound; it does not read the private-key input or use message statistics. After recovery, the public encryption data supplies R, salt and IV for decryption.

For d = 1337, the search recovers the key after 1,337 candidates and decrypts “Meet me at the university library at noon.” The worst-case cost grows linearly with the advertised bound; for a uniformly chosen key in this range the average is 2,048 candidates.


Difference from Caesar cryptanalysis: the Caesar attack selects a likely plaintext using language frequencies and can be wrong on short text. The ECC attack recognizes the key by exact point equality. It works without knowing the language and can recover d from Q even before receiving a ciphertext. Both exploit weaknesses of these examples, but the ECC search exploits the restricted secret-key space rather than plaintext letter statistics.


Why properly configured ECC is different: a normal secp256k1 private scalar is sampled unpredictably from 1,…,n−1, approximately 2²⁵⁶ possibilities. Extending this enumeration to that range is infeasible. The example demonstrates the effect of insufficient key entropy; it does not show a practical break of correctly configured secp256k1. The construction is for learning and should not protect real secrets.
